# Practice-First Learning

## Purpose

Define the learning philosophy: users acquire practical website-design understanding while building their own website with the predefined component portfolio.

## Learning through real activities

The primary learning experience is the actual design workflow:
1. Browse a component type and its available samples.
2. Inspect sample previews.
3. Select a candidate.
4. Explicitly confirm and insert it using the M06 flow.
5. Configure supported content fields and finite options.
6. Observe the result in the responsive canvases.
7. Compare alternatives and, if desired, replace the sample.
8. Understand the practical result through the page preview.

This workflow teaches through experimentation without turning the builder into a detailed visual editor.

## Practice principles

- Use the user's active project as the learning context.
- Let users inspect examples without changing their project.
- Keep practice reversible within the operations supported by M06; do not imply undo/redo or history that the MVP does not provide.
- Never require completion of a separate lesson before a user can perform a design action.
- Do not invent mandatory exercises, quizzes, scores, or reward loops.
- Users can pause a mission and work elsewhere.
- Examples must not be presented as objectively best or automatically selected.

## Learning through comparison

When users inspect alternative samples, they can learn from visible differences in:
- Layout and hierarchy.
- Content presentation.
- Use of imagery or placeholders.
- Responsive presentation.
- The intended role of the component.

M07 defines catalogue sample metadata and preview conventions. M08 uses those previews as learning opportunities and does not require extensive technical commentary for every sample.

## Relationship to mission completion

Learning activity is not itself a mission-completion requirement unless the relevant level explicitly defines a user decision or outcome. Viewing examples, opening help, or reading optional guidance must not be treated as completing a design decision.

M01's objective mission-completion rules remain authoritative.

## Boundaries

- No Figma-like editing, arbitrary CSS, geometry, or nested-element editing.
- No automatic sample selection, insertion, replacement, or arrangement.
- No AI-generated lessons or recommendations in the initial product.
- No persistence, autosave, undo/redo, or history beyond M04/M05/M06's temporary in-memory model.

## Acceptance criteria

- [ ] Learning is embedded in real component selection and composition activities.
- [ ] Sample inspection does not mutate project composition.
- [ ] Actual insertion follows M06's explicit confirmation and position flow.
- [ ] Supported content/configuration boundaries remain intact.
- [ ] No mandatory standalone course or reward mechanics are introduced.
- [ ] Learning activity does not falsely satisfy mission requirements.
