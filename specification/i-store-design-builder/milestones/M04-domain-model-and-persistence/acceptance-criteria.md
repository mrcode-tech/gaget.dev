# M04 Acceptance Criteria

## Specification
- [ ] Project/page/composition boundaries described.
- [ ] Catalogue samples and inserted instances distinguished.
- [ ] Instance content/configuration independent.
- [ ] Typed sample-defined fields and bounded options described.
- [ ] Shared and breakpoint-specific data separated.
- [ ] Responsive layouts reference shared instances and preserve M02 constraints.
- [ ] Placeholder and optional asset-reference concepts defined without asset infrastructure.
- [ ] Progression separate from composition and aligned with M01.
- [ ] Sample-version compatibility considered without migration implementation.
- [ ] MVP explicitly browser-only, in-memory and temporary.
- [ ] Persistence, auth, autosave, recovery, version history, import and collaboration deferred; M14 local export exception documented.
- [ ] Generic website scope and bounded editing preserved.
- [ ] Future architecture technology-neutral.

## Boundary
These criteria validate the specification, not implementation or test evidence.


## MVP C amendment

M04's project model remains temporary and in-memory. Explicit JSON/Markdown export and optional ZIP handoff are defined by M14 and do not count as persistence. Project import remains deferred.
