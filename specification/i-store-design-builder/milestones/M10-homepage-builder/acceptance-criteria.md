# M10 — Acceptance Criteria

- [ ] A project has exactly one identifiable homepage.
- [ ] The section library exposes the agreed generic section families.
- [ ] Section categories are discoverable without being mandatory.
- [ ] Multiple distinct samples can be browsed for a populated section type.
- [ ] Sample preview and comparison do not mutate the project.
- [ ] Insertion requires explicit confirmation and user-selected placement.
- [ ] Section operations follow M06 lifecycle and validation rules.
- [ ] Only sample-defined content fields and finite options are editable.
- [ ] Real, draft, placeholder, and missing content states are distinguishable.
- [ ] The user can define or mark not applicable the primary visitor action according to mission rules.
- [ ] Shared header/navigation/footer references do not create accidental duplicates.
- [ ] M09 identity tokens apply only through explicit sample compatibility.
- [ ] Desktop/tablet/mobile membership and responsive behavior follow M01/M06.
- [ ] Optional/irrelevant sections are not forced.
- [ ] No AI or automatic section selection, insertion, replacement, or ordering exists.
- [ ] Generic examples work beyond the first store-focused journey.
- [ ] No persistence, autosave, history, backend, or authentication is introduced.
