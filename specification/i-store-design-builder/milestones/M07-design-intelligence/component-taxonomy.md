# Component Taxonomy

## Purpose

Define the generic, hierarchical classification used to organize the website component portfolio. Classification describes a component's role; it must not dictate a user's website structure or make selection decisions.

## Taxonomy principles

1. Organize primarily by high-level component type.
2. Use hierarchical categories and subcategories for understandable browsing.
3. Keep functional component type distinct from visual style and website purpose.
4. Make the taxonomy generic across stores, professionals, creators, organizations, non-profits, and other website purposes.
5. Establish broad coverage early; populate samples progressively.
6. Permit taxonomy extension through documented review rather than ad hoc labels.
7. Avoid duplicating a component type solely because it appears in multiple website contexts. Use purpose classifications instead.

## Initial category map

| Category | Initial component types / subcategories |
|---|---|
| Navigation | Header, navbar, primary navigation, sidebar navigation, menu, breadcrumbs, pagination |
| Introduction | Hero, page introduction, title banner, announcement banner |
| Content | Text section, image-and-text section, article section, feature section, statistics, editorial/story section |
| Products and services | Product grid, product list, product category presentation, featured product, service cards, service detail, pricing |
| Media and portfolio | Image gallery, video section, portfolio grid, image showcase, case-study presentation |
| Social proof | Testimonials, reviews, ratings, client logos, trust indicators |
| Conversion and actions | Call to action, contact form, newsletter signup, booking/action panel |
| Commerce | Product highlights, promotions, shopping benefits, category discovery, cart-related presentation |
| Information | FAQ, team, about, timeline, process, location, opening hours, contact information |
| Footer and closing | Footer, contact footer, multi-column footer, legal links, closing navigation |
| Utility and feedback | Search, filters, alerts, empty states, loading states, error states |

This is the initial taxonomy baseline, not an exhaustive claim that every possible website pattern is already represented. Exact subcategory boundaries may be refined when samples are authored, without changing the primary organizational principles.

## Classification dimensions

### Component category and type

Every sample belongs to exactly one primary component type and inherits its category. The type identifies the component's functional responsibility, not its appearance.

### Visual style

Use a controlled, documented, extensible set of primary visual-style labels. Initial vocabulary may include:

- Minimal
- Editorial
- Contemporary
- Expressive
- Luxury
- Classic
- Organic
- Geometric
- Playful
- Industrial

These labels are descriptive discovery aids, not quality rankings or mutually exclusive design rules. Add or revise labels through taxonomy governance. A sample may have one primary style and, where useful, a small number of secondary style descriptors.

### Website purpose

Optional purpose classifications may include:

- Store / commerce
- Professional services
- Personal portfolio
- Creator / publication
- Organization / non-profit
- Community
- Event
- General business

Purpose labels describe contexts where a sample may be useful. They must not restrict users from selecting a sample for another purpose.

### Keywords

Samples and component types may carry searchable terms, synonyms, and plain-language phrases. Keywords supplement, but do not replace, the controlled taxonomy.

## Classification rules

- Every published sample has one stable component type.
- Category membership is derived from the component type.
- Visual style and website purpose are optional secondary classifications.
- Search terms do not create new component types.
- Classification changes must not change the sample's identity or silently alter existing instances.
- Do not use popularity, quality scores, or automated rankings as taxonomy dimensions.

## Governance and extension

A proposed new category or component type should document its purpose, distinction from existing types, representative content needs, likely sample diversity, responsive considerations, and relevance across website purposes. Prefer extending an existing type with new samples when the functional role is unchanged.

## Acceptance criteria

- [ ] Major generic component categories are represented.
- [ ] Each component type has a clear functional definition.
- [ ] Category, type, visual style, purpose, and keyword dimensions are distinct.
- [ ] The taxonomy supports store-focused and non-store websites.
- [ ] Taxonomy extension does not require immediate sample population.
- [ ] Classification does not introduce ranking or automatic selection.
