# Product Glossary

| Term | Meaning |
|---|---|
| User | The person defining and composing their website design. |
| Project | The website initiative being designed, including its purpose, audience, and intended outcome. |
| Workspace | The application area containing levels, canvas, and component library. |
| Canvas | Bounded visual wireframe preview of the website page being designed. |
| Level | A stage in the guided journey that introduces a group of related design decisions. |
| Mission | A specific task within a level, with an objective and completion criteria. |
| Progress | A record of completed and incomplete missions; not a score or reward. |
| Component | A high-level website building block, such as a hero, gallery, navigation, or FAQ. |
| Pattern | A curated layout/presentation option for a component type. |
| Component option | A user-configurable choice available within a selected pattern. |
| Section | A meaningful region of a webpage, composed from a selected component/pattern. |
| Page | A website view with an ordered set of sections and shared site elements. |
| Component library | The browsable catalogue from which users independently select components and patterns. |
| Content placeholder | A visible indication of where text or other content will be supplied later. |
| Image placeholder | A wireframe region that communicates intended image placement and purpose without requiring a final image. |
| Reference asset | An optional user-provided image, logo, or photo used to communicate intent. |
| Responsive pattern | A curated way for a component to adapt across desktop, tablet, and mobile. |
| Wireframe design | A structured visual representation of page hierarchy, sections, content slots, and image placement. |
| Partial design | A saved project that has not completed every required mission but still communicates current decisions and remaining work. |
| Handoff summary | A human-readable and/or structured description of the user's purpose, design decisions, placeholders, and unfinished work. |

## Additional M01 terms

| Term | Meaning |
|---|---|
| Required mission | A mission whose objective decisions must be satisfied for overall design completion, unless explicitly marked Not needed where supported. |
| Optional mission | A mission that adds useful detail but does not block level or overall completion. |
| Not needed | An explicit user decision that a mission or component is not relevant where that choice is offered. |
| Mission status | Not started, In progress, Complete, or Needs review. |
| Level completion | A user-declared state indicating the user considers a level finished; it does not waive unfinished missions. |
| Overall design completion | The state reached when all applicable required missions are complete and the user confirms the final review. |
| Needs review | A mission state indicating that an earlier decision changed and the mission may be affected. |
| Breakpoint canvas | One of the desktop, tablet, or mobile views of the same website design. |
| Shared component | A component whose identity, content, and shared configuration are common across breakpoint canvases. |
| Breakpoint layout | The independently editable arrangement and visibility state of shared components at a particular breakpoint. |
| Component visibility | Whether a shared component is shown in a specific breakpoint; hiding it does not delete it. |
